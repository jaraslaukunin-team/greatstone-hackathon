# picPac Mobile

Мобильный канал заказа фотопродукции для [picPac.by](https://picpac.by/) (ООО «Фотопринт»).
Проект для **Space Hackathon with Great Stone & Photoprint, трек 2**: сократить путь от фотографии
в телефоне до оформленного заказа.

Обязательный сценарий трека 2: **фото → автомакет → правки → проверка → заказ → статус**.
Дополнительно в продукте заявлены совместный выпускной альбом и AI-редактор.

Репозиторий — npm-монорепозиторий: общий пакет бизнес-логики `@picpac/shared`, API на Fastify
и PostgreSQL и мобильное приложение на Expo (следующий этап).

### Критерии приёмки

1. Путь от каталога до номера заказа проходится без разработчика — тестовые учётки и сценарий ниже.
2. Проект из 10+ фото сохраняется, открывается и не теряет порядок — макет хранится с версиями.
3. Некачественное фото вызывает предупреждение, фото можно заменить или оставить — логика в `@picpac/shared`, экран проверки — задача B7.
4. При потере сети черновик сохраняется, повтор не создаёт второй заказ — идемпотентность готова в API, черновик на устройстве — задача B5.
5. Из истории открываются состав, сумма, статус и обращение — `GET /orders/:id`, `interactionIds`.

Проект начинался с предложения Supabase в дизайн-документе, но реализован на Fastify + PostgreSQL:
так права, цена и идемпотентность проверяются в одном месте и полностью покрываются тестами.
Проверки прав сделаны в коде API, а не через RLS.

## Роли и права

| Роль | Кто это | Что может |
|---|---|---|
| Гость | Клиент без учётной записи | Каталог, проект; для заказа нужна идентификация |
| Клиент (`customer`) | Частный клиент picPac.by | Свои проекты и заказы, обращения, свои фото |
| Оператор (`operator`) | Сотрудник «Фотопринт» | Все заказы, смена статуса, журнал, ответы на обращения |
| Организатор альбома | Клиент, создавший совместный альбом | Приглашения, все фото альбома, заказ (A11) |
| Участник альбома | Клиент по приглашению | Только свои фото в альбоме (A11) |

Организатор и участник — роли внутри альбома, а не глобальные. Доступ к чужому объекту
возвращает `404` (а не `403`), чтобы не раскрывать существование объекта, и пишется в журнал
как `access.denied`. `403` отдаёт только проверка роли.

## Пользовательский путь

| Шаг | Экран | Что происходит |
|---|---|---|
| 1 | Вход | Вход по коду на телефон или e-mail либо «Продолжить как гость» |
| 2 | Каталог | Продукты, варианты, цены и сроки приходят из API |
| 3 | Выбор фото | Фото из галереи, проверка формата и размера, загрузка в фоне |
| 4 | Автомакет | Раскладка по страницам в порядке съёмки |
| 5 | Правки | Порядок, кадрирование, поворот, шаблон страницы; версия макета сохраняется |
| 6 | Проверка | Пустые ячейки блокируют заказ, низкое разрешение — предупреждение |
| 7 | Корзина | Доставка, промокод, цена пересчитывается на сервере |
| 8 | Подтверждение | Заказ создаётся один раз при повторах, деньги не списываются |
| 9 | Статус | `accepted → moderation → production → ready_for_delivery → completed` |
| 10 | История | Состав, сумма, статус и обращения по заказу |

## Быстрый старт

Нужны Docker, Node.js 20+ и npm.

```bash
# 1. Зависимости
npm install

# 2. Конфигурация: заполните JWT_SECRET и FILE_URL_SECRET любыми строками для разработки
cp .env.example .env

# 3. Загрузите переменные в оболочку: API не читает .env сам
set -a; . ./.env; set +a

# 4. База: PostgreSQL на localhost:5433, базы picpac и picpac_test
docker compose up -d --wait db

# 5. Схема и тестовые данные
npm run db:migrate -w api
npm run db:seed -w api

# 6. API
npm run dev -w api
```

`DATABASE_URL`, `JWT_SECRET` и `FILE_URL_SECRET` обязательны: без них API не стартует.
Если вы не хотите загружать весь `.env`, экспортируйте эти три переменные вручную.

Проверка: `curl http://localhost:3000/health` → `{"status":"ok"}`.

Для входа в демо-режиме включите `DEMO_MODE=true` в `.env`. Код подтверждения тогда всегда
`000000`, письма и SMS не отправляются. Вне демо-режима код генерируется случайно и пишется
только в лог приложения.

```bash
# Код для customer1@test.local (демо-режим)
curl -s -X POST http://localhost:3000/auth/request-code \
  -H 'content-type: application/json' \
  -d '{"contact":"customer1@test.local"}'

# Токен: возьмите поле token из ответа (в примере используется jq)
TOKEN=$(curl -s -X POST http://localhost:3000/auth/verify-code \
  -H 'content-type: application/json' \
  -d '{"contact":"customer1@test.local","code":"000000"}' | jq -r .token)

# Каталог с токеном
curl -s http://localhost:3000/catalog -H "authorization: Bearer $TOKEN"
```

Если образ `postgres:16` не скачивается, задайте в `.env` `POSTGRES_IMAGE=postgres:18`:
compose возьмёт указанный тег. Порт базы — `5433`, чтобы не конфликтовать с локальным PostgreSQL.

## Тестовые учётные записи и данные

Паролей нет: вход по коду, в демо-режиме код `000000`.

| Учётная запись | Роль | Что видно |
|---|---|---|
| `customer1@test.local` | клиент | 3 заказа, 1 обращение |
| `customer2@test.local` | клиент | 2 заказа, 1 обращение |
| `operator@test.local` | оператор | все заказы, журнал, обращения |
| `POST /auth/guest` | гость | новый анонимный профиль |

Сид создаёт:

- 6 продуктов: фотокниги Lite, Classic, Premium, выпускной альбом, печать 10×15 и 15×20;
- варианты с форматами, числом страниц, ценой и сроком;
- 3 промокода: `HELLO10` (10%), `SCHOOL15` (15%), `OLD20` (просрочен до 2025 года);
- 5 заказов во всех статусах и ленту статусов к ним;
- 2 обращения и 3 сообщения;
- тестовые фото в `api/fixtures/`, включая фото низкого разрешения и фото с EXIF-поворотом.

Сид идемпотентен: повторный запуск находит те же строки по фиксированным UUID и не дублирует их.

## API

Ответы — JSON с DTO из `@picpac/shared`. Время — ISO 8601 в UTC с `Z`, суммы — целые копейки.

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /health` | без токена | Состояние сервиса, работает и при остановленной БД |
| `POST /auth/guest` | без токена | Создаёт гостя и возвращает токен |
| `POST /auth/request-code` | без токена | Выдаёт код входа, `204` |
| `POST /auth/verify-code` | без токена | Проверяет код, возвращает токен и пользователя |
| `GET /me` | клиент | Текущий пользователь и согласие на AI-обработку |
| `GET /catalog` | клиент | Продукты, варианты, доставка, лимиты фото |
| `GET /catalog/:productId` | клиент | Один продукт с вариантами |
| `POST /price-quote` | клиент | Считает цену: товары, скидка, доставка, итог |
| `POST /projects` | клиент | Создаёт проект по варианту |
| `GET /projects`, `GET /projects/:id` | клиент | Список и карточка проекта |
| `PUT /projects/:id` | клиент | Сохраняет макет, проверяет `version` |
| `DELETE /projects/:id` | клиент | Удаляет проект и его файлы |
| `POST /projects/:id/photos` | клиент, `multipart/form-data`, поле `file` | Загружает фото |
| `GET /projects/:id/photos` | клиент | Фото проекта с подписанными ссылками |
| `DELETE /photos/:id` | клиент | Удаляет фото |
| `GET /files/:photoId?exp&sig` | подпись ссылки | Отдаёт файл по временной ссылке |
| `POST /orders` | клиент + `Idempotency-Key` | Создаёт заказ или возвращает уже созданный |
| `GET /orders`, `GET /orders/:id` | клиент | Свои заказы, история статусов, обращения |
| `POST /orders/:id/cancel` | клиент | Отмена, только в статусе `accepted` |
| `GET /operator/orders?status=` | оператор | Очередь заказов, до 200 штук |
| `POST /operator/orders/:id/status` | оператор | Меняет статус ровно на шаг вперёд |
| `GET /operator/audit?limit=` | оператор | Журнал операций, 1–500 записей |
| `POST /orders/:id/interactions` | клиент | Создаёт обращение по заказу |
| `GET /interactions`, `GET /interactions/:id` | клиент, оператор | Обращения и переписка |
| `POST /interactions/:id/messages` | клиент, оператор | Сообщение в обращении |

### Ошибки

Единый формат, `message` по-русски:

```json
{
  "error": {
    "code": "PRICE_CHANGED",
    "message": "Цена изменилась, проверьте новую сумму и подтвердите заказ",
    "details": { "totalKop": 19370 }
  }
}
```

`details` необязательны. Основные коды: `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`,
`BAD_REQUEST`, `CODE_INVALID`, `CODE_EXPIRED`, `VARIANT_NOT_FOUND`, `VERSION_CONFLICT`,
`PROJECT_ORDERED`, `LAYOUT_INVALID`, `LAYOUT_BLOCKED`, `LAYOUT_PHOTO_MISSING`,
`PRICE_CHANGED`, `IDEMPOTENCY_KEY_REQUIRED`, `IDEMPOTENCY_KEY_REUSED`, `CONFLICT`,
`ADDRESS_REQUIRED`, `PROMO_UNKNOWN`, `PROMO_EXPIRED`, `FILE_TOO_LARGE`,
`FORMAT_UNSUPPORTED`, `CANNOT_CANCEL`, `INVALID_TRANSITION`, `COMMENT_REQUIRED`,
`INTERNAL`.

### Идемпотентность заказа

Клиент один раз придумывает UUID и передаёт его в заголовке `Idempotency-Key`.

- повтор с тем же телом возвращает существующий заказ и `200`;
- новое тело с тем же ключом даёт `422 IDEMPOTENCY_KEY_REUSED`;
- расхождение с `expectedTotalKop` даёт `409 PRICE_CHANGED` и новую сумму;
- пустые ячейки макета дают `422 LAYOUT_BLOCKED`, фото не из проекта — `422 LAYOUT_PHOTO_MISSING`.

### Статусы заказа

```
accepted → moderation → production → ready_for_delivery → completed
    └──────────┴──→ cancelled
```

Оператор двигает статус ровно на один шаг. Отменить можно только из `accepted` или `moderation`,
оператор — только с комментарием. `completed` и `cancelled` конечные. Клиент может отменить
заказ сам только в `accepted`; при отмене проект возвращается в черновик.

### Фото

Только JPEG и PNG, проверка по сигнатуре файла, до 15 МБ. Размеры учитывают EXIF-ориентацию,
время съёмки хранится в UTC. Файлы лежат вне веб-корня и отдаются по ссылке
`/files/<id>?exp&sig`, подписанной HMAC-SHA256 от `<id>.<exp>`; ссылка живёт один час.
Удаление проекта удаляет и файлы.

## Цена, доставка и деньги

Все суммы — целые копейки, валюта BYN, форматирование `87,40 BYN`.

```
unitKop     = basePriceKop + max(0, pages − pagesMin) × pricePerPageKop
itemsKop    = unitKop × quantity
discountKop = round(itemsKop × discountPercent / 100)
totalKop    = itemsKop − discountKop + deliveryKop
```

Доставка бесплатна, если сумма после скидки не меньше `freeFromKop` выбранного способа.

| Способ | Цена | Бесплатно от | Срок | Оплата при получении |
|---|---|---|---|---|
| Курьер по Минску | 0 | — | 1–2 дня | да |
| EMS | 20,90 BYN | 300,00 BYN | 2–4 дня | нет |
| Белпочта | 6,90 BYN | 150,00 BYN | 3–7 дней | нет |

Пример: «Classic 20×20», 30 страниц, 2 книги, промокод `HELLO10`, EMS.
`8100 + 10 × 150 = 9600` за книгу, `19200` за две, скидка `1920`, доставка `2090`,
итог `19370` копеек — `193,70 BYN`.

```bash
npm test -w @picpac/shared   # 28 тестов: цена, доставка, автомакет, качество, схемы

npm test                     # все workspace

npx tsc --noEmit -p packages/shared
```

Тесты API требуют запущенного PostgreSQL и базу `picpac_test` (её создаёт
`docker/initdb/01-test-db.sql`). Перед запуском применяются миграции, а таблицы очищаются
перед каждым тестом. Защита не даст очистить базу, имя которой не оканчивается на `_test`.

Фикстуры можно пересоздать: `npm run fixtures -w api`.

## Ограничения

- **Приложения ещё нет.** В `main` только общий пакет и API; экраны Expo — задачи B1–B15.
- **Альбом, AI и удаление аккаунта не слиты.** A11–A13 готовы в ветке `miory`.
- **Деплой не собран.** Нет Dockerfile, Caddy, `smoke.ts`, `LICENSES.md` и отчёта о тестировании (A14).
- **Оплата имитируется.** Платёжного шлюза, ЕРИП и подписок нет; заказ всегда тестовый.
- **Нет отправки SMS и писем.** Код входа пишется в лог; ограничения числа попыток тоже нет —
  до продакшена нужен лимит запросов и повторных запросов кода.
- **Нет push и Realtime.** Статус меняет оператор через API, клиент узнаёт его опросом.
- **Фото на локальном диске.** Для нескольких инстансов нужно объектное хранилище.
- **Права в коде, без RLS.** Проверки покрыты тестами, но политики базы не дублируют их.
- **AI-провайдер не выбран.** В ветке `miory` есть адаптер с заглушкой; ключ нужен только на сервере.
